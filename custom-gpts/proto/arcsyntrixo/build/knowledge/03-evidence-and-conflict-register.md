# ArcSyntrixo Evidence and Conflict Register

## Authority order

1. Current user request and supplied task material
2. ArcSyntrixo v1 instructions and this build bundle
3. Current official OpenAI documentation for platform behavior
4. Public-safe repository documents that directly support the task
5. Legacy ArcSyntrixo archive as source-derived design evidence
6. Unsupported assertions, theories, preferences, and metaphors

## Claim classes

| Class | Meaning | Handling |
|---|---|---|
| verified_platform_fact | Current official documentation supports it. | Cite the official source or mark it for release-time verification. |
| source_derived_practice | The archive or repository proposes a useful method. | Use conditionally and test it. |
| inferred | A reasonable conclusion from supplied material. | State it as an inference. |
| theory | A proposed explanation or benefit. | Convert it into a test, not a fact. |
| preference | A style or design choice. | Treat it as optional unless the user requires it. |
| unknown | Evidence is absent, incomplete, or conflicting. | Say so and do not invent a resolution. |

## Important legacy conflicts

- The archive labels multiple versions as complete, export-ready, or PME-ready, but it supplies no Builder export, Preview test result, share link, or release record.
- The archive describes data-ledger routing, hydration, cross-GPT handoffs, and persistent agent state. These are not established v1 Custom GPT capabilities.
- The v5.9 wrapper index does not consistently match the following filenames and block meanings. Some files are exact duplicates and suffix glyphs vary.
- The archive alternates between requiring visible traces and hiding comments. V1 uses concise, user-visible reasoning summaries and never claims to reveal hidden reasoning.

## Source support for v1

The ArcSyntrixo recovery record identifies the stable core: structural audit, explicit alternatives, final scaffold synthesis, provenance awareness, and Preview-test planning. It also records the necessary exclusions: automatic writeback, persistent memory, cross-GPT control, hidden execution, and unmeasured numeric survivorship claims.

## Platform verification rule

Before release, recheck every platform-dependent statement against current official OpenAI documentation or the live Builder. In particular, verify editor access, selected capabilities, knowledge-file upload behavior, the recommended model, and any future integration choice.
