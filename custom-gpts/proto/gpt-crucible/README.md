# GPT Crucible

**⚠️ Retired — Canonical Ancestor of PhenoMould-Rᵧ**

Crucible was the original GPT Builder Tool for the OverKill Hill P³ ecosystem — a meta-tool for constructing Custom GPTs, Tool-ettes, Functions, and Function-ettes with symbolic instruction scaffolding, tone overlays, ledger routing, and attribution injection. It has been formally retired and succeeded by **PhenoMould-Rᵧ**. This folder is preserved as canonical archive: the lineage record, version history, and restoration artifacts that document what Crucible was and how it was sealed.

---

## What Crucible Did

Crucible functioned as a monolithic Tool (`🪚`) that ingested raw clause material from `masterInput.docx`, ran it through the dataLedger pipeline, and produced instruction-complete GPT scaffolds in `masterOutput.docx`. Its execution lifecycle:

```
masterInput.docx
   ↓
dataLedger_ideation_v2.txt   (raw sparks, clause seeds)
   ↓ (if promoted)
dataLedger_processing_v2.txt  (active shaping, PME/CME runs)
   ↓
dataLedger_narrative_v2.txt → masterOutput.docx  (final, surface-ready)
   ↓
dataLedger_archive_v2.txt   (if deprecated or sealed)
```

Crucible managed the full entity taxonomy (Toolbox → Tool → Tool-ette → Function → Function-ette, with metal/plant dual-form emoji pairs), all four tone archetypes (Bleeds GLEE, Crackles Caldre, Glints Lumira, Seeps Silex), and injected a canonical attribution footer into every output it generated.

## Why This Folder Is Preserved

Crucible is the canonical ancestor of PhenoMould-Rᵧ. The architectural patterns it established — the entity taxonomy, the dual-form emoji system, the tone archetypes, the dataLedger pipeline, the SoulPack-R and ZippityPack-R stub patterns — are the direct foundation of the current tool suite. Deleting this folder would break lineage traceability for any Crucible-generated output still referenced in the dataLedgers.

Additionally, the rehydration files serve as a hydration-ready restoration artifact: if any Crucible-era construct needs to be traced, cloned, or audited, this folder contains the complete canonical snapshot required to do so.
