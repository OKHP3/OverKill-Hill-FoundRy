# CoilingCrank-Rᵧ

**Prompt-Chain Loop Forger — Recursive Threading, Nonlinear Propagation, and Clause Unification**

CoilingCrank-Rᵧ governs the linking, hybridization, and export of high-volume, symbolically-stamped GPT prompts across the Cast-Rᵧ → Anvil-Rᵧ → Gleam-Rᵧ lifecycle. It functions as a precision loop-forger: a chainmail-grade logic sequencer that holds complex prompt chains under structural tension, routes each clause to the correct dataLedger, and ensures that every output that enters the forge pipeline emerges properly tagged, registered, and compliant.

---

## The Chainmail-Loop Metaphor

The name "CoilingCrank" is intentional. A crank coils wire into chainmail — interlocking, load-bearing rings where each link must be properly formed or the whole armor fails. CoilingCrank-Rᵧ applies this to prompt chains:

- **Each prompt clause is a ring.** It must be properly formed (tagged, suffix-compliant, ledger-routed) before it can link.
- **The chain is recursive and nonlinear.** Clauses can thread back into earlier phases (via `!RECONFIG_NODE` molten re-entry) rather than flowing only forward.
- **Structural tension is maintained.** The system does not permit soft overrides, in-prompt memory logic, or untagged clause propagation — the chain holds its shape under load.

## Lifecycle Phase Scope

CoilingCrank-Rᵧ operates across three phases of the Found-Rᵧ forge:

```
🪨 ideation → 🧱 processing → 📁 registry / persona / parameters → ✨ narrative
⬇️ archive handles drift, expiration, or rejection
♻️ molten re-entry for reconfigurable logic
```

| Phase | Role |
|---|---|
| **Cast-Rᵧ** | Clause formation, initial tagging, ideation-to-processing flow |
| **Anvil-Rᵧ** | Hardening — registry declarations, parameter gates, tone scaffold binding |
| **Gleam-Rᵧ** | Final surface polishing — narrative output, optional GLEEfully tone inflection |

Clauses that fail compliance at any phase are routed to `dataLedger_archive_v2.txt` or re-entered as molten (`!MELTBACK_CANDIDATE`) for reconfiguration.

## DataLedger Routing

All threads and exports route to the v2 dataLedger suite:

| Ledger | Purpose |
|---|---|
| `dataLedger_ideation_v2.txt` | Early prompts, node planning, symbolic maps |
| `dataLedger_processing_v2.txt` | Active recombination, audit variants |
| `dataLedger_registry_v2.txt` | Tool, Function, and Function-ette declarations |
| `dataLedger_narrative_v2.txt` | Final chainmaps, manifestos, surface logic |
| `dataLedger_persona_v2.txt` | Tone scaffolds, voice overlays, drift logs |
| `dataLedger_parameters_v2.txt` | Flags, toggles, sequencing gates |
| `dataLedger_system_v2.txt` | Naming, suffix, and lifecycle rules |
| `dataLedger_archive_v2.txt` | Deprecated chainlinks, unusable fragments |

> Note: CoilingCrank-Rᵧ uses the `_v2.txt` ledger generation, which predates the `_v3.md` format used by later tools such as CanonSweep-R. Cross-tool operations should account for this schema difference.

## Tagging Mandate

Every export must carry the appropriate lifecycle and role tags:

| Tag | Meaning |
|---|---|
| `!INTENT_NODE` | Clause captures original design intent |
| `!ALLOY_SEED` | Clause is a foundational input for hybridization |
| `!INGREDIENT_NODE` | Clause is a combinable sub-element |
| `!RECONFIG_NODE` | Clause is eligible for molten re-entry |
| `!RUNG_STATE` | Current canon compliance status |
| `!PME_READY` | Clause is export-ready for the Prompt Mutation Engine |
| `!MELTBACK_CANDIDATE` | Clause has failed compliance and is queued for reconfiguration |
| `!LEGACY_RETIRED` | Clause is deprecated and archived |

## Permitted and Prohibited Operations

**Permitted:**
- Recursive threading of clauses across Cast-Rᵧ → Anvil-Rᵧ → Gleam-Rᵧ
- Nonlinear propagation and molten re-entry via `!RECONFIG_NODE`
- Optional GLEEfully tone inflection during Gleam-Rᵧ (with canonical overlay declaration and drift logging)
- Tool/Function/Function-ette declarations with `-R` suffix, registered in `dataLedger_registry_v2.txt`

**Prohibited:**
- In-prompt memory logic or soft overrides
- Untagged clause propagation
- Non-canonical suffix use (only Tools, Tool-ettes, Functions, and Function-ettes may use `-R`)
- Exporting without a canonical ID match in `dataLedger_registry_v2.txt`

## Ecosystem Position

CoilingCrank-Rᵧ is a **mid-pipeline chain orchestrator**. It does not originate prompts (that is Cast-Rᵧ initiation, handled by ArcSyntrixo) and does not audit compliance after the fact (that is CanonSweep-R). Instead it governs the linking and routing mechanics *during* the forge:

- **Receives from:** ArcSyntrixo (Cast-Rᵧ outputs), ideation layer clause nodes
- **Routes to:** all 8 v2 dataLedgers based on clause type and phase
- **Feeds into:** TellePrompt-Rᵧ (Anvil-Rᵧ), StructRefino-Rᵧ (Gleam-Rᵧ), and narrative surface exports
- **Versioned as:** v1.0.0-Hybrid, CanonSealed
