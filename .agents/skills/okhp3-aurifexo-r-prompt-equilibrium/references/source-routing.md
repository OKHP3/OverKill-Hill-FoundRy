# Aurifexo-R Source Routing

## Authority order

1. The current user request controls the immediate task.
2. This skill controls the procedure and safety boundary.
3. The current, specific reference controls its stated subject.
4. A newer and more specific source outranks an older general source when provenance is clear.
5. General model knowledge is a fallback and must be labeled when it is not source-backed.

When sources conflict, preserve both claims, state the conflict, choose the applicable authority, and record the reason.

## Evidence classes

- `supported`: directly grounded in an available source or visible tool result.
- `inferred`: derived from multiple sources and labeled as inference.
- `theory`: proposed mechanism that needs evaluation.
- `preference`: owner or user design choice.
- `unverified`: plausible but not confirmed by the available evidence.
- `unsupported`: not found in the available evidence.

## Portable boundaries

Uploaded files, Knowledge files, Project Files, and hydration snapshots are read-only inputs. The skill may produce a replacement or export block, but it must not claim that it mutated the source. Raw thread URLs and hidden platform state are provenance or context, not runtime dependencies.
