# ReFolDec Vocabulary

## ReFolDec

The Recursively Folding Codec. A bidirectional framework for folding raw thought into structured artifacts and unfolding mature artifacts back into primitives, patterns, and reusable instructions.

## Fold

The operation of moving material into a more mature, structured, durable, or reusable state.

Examples:

- raw thought → note;
- note → concept;
- concept → process;
- process → artifact;
- artifact → system.

## Unfold

The operation of decomposing a mature artifact into source primitives, assumptions, dependencies, patterns, gaps, or reusable parts.

Examples:

- document → outline;
- diagram → process records;
- Agent Skill → workflow assumptions;
- canon → concepts and constraints.

## Refold

The operation of recomposing improved primitives into a stronger artifact.

## xME

x Maturation Engine. The earlier name for upward movement from less mature to more mature states.

## xIE

x Inversion Engine. The earlier name for downward movement from mature artifact to source primitives.

## xMIE

x Maturation / Inversion Engine. The bidirectional theoretical mechanic behind ReFolDec.

## Artifact

Any captured object that can be transformed: note, prompt, diagram, process, document, skill, schema, story element, or system description.

## Maturity state

The current degree of structure, validation, publication, and reuse-readiness of an artifact.

## Process-capture

The act of capturing the steps, context, actors, decisions, tools, constraints, and reuse path of a repeatable activity.

## Process of process-capture

The recursive act of capturing how process-capture itself works so that it can be improved, reused, taught, automated, or delegated.

## Agent Skill

A packaged instruction set that helps an AI agent perform a specialized task reliably, often using supporting resources, scripts, and constraints.

## Capture plane

The private surface where rough material is collected and shaped. In the OKHP³ operating model, this is usually Notion.

## Canonical plane

The public, versioned, durable surface where cleaned artifacts are published. In the OKHP³ operating model, this is usually GitHub.
