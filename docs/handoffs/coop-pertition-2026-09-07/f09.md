# F09 — Keyboard and dialog acceptance

## Scope

Implemented only `artifacts/custom-gpt-creator/tests/coop-keyboard.e2e.ts`.
The test exercises keyboard activation for project selection, capability backup
import confirmation, and project deletion. No application source, CSS,
dependencies, configuration, or shared checkout files were changed.

## Evidence

- `keyboard can select projects and accept the import confirmation` passes with
  keyboard focus and Enter on the duplicate/import confirmation controls, and
  verifies the imported project becomes active.
- `keyboard activation reaches delete and preserves the browser dialog contract`
  passes with keyboard focus and Enter on Delete project, verifies a native
  `confirm` dialog and its message, accepts it, and verifies the replacement
  empty project.
- The native browser confirmation dialog is observable through Playwright's
  `dialog` event but cannot be inspected as an in-page DOM focus target. This
  is the remaining keyboard-test limitation; the test records its type/message
  and accepts it through the browser dialog API.
